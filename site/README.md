# co:op website

This folder holds co:op's homepage and docs, and GitHub Pages serves them from here. The
pages are static HTML, CSS and JavaScript. There's no framework, no build step at serve time
and no `node_modules`. The look follows `brand/DESIGN.md`.

```
site/
  index.html            the homepage (generated: never edit it by hand)
  docs.html             the docs (hand-written, except its generated terminal windows)
  llms.txt              the CLI reference for language models (generated by make docs)
  site.webmanifest      PWA manifest (name, theme color, app icons)
  robots.txt            allow-all + sitemap pointer
  sitemap.xml           the two pages, for crawlers
  CNAME                 the custom domain, coop.dryga.com
  README.md             this file
  assets/
    css/site.css        the design system, shared by both pages
    js/site.js          copy buttons, the agent picker, the homepage story, the scenes, the docs contents
    js/analytics.js     Mixpanel: autocapture, page views, session replay and the copied setup commands
    fonts/              Inter (SIL Open Font License)
    img/                favicon + app icons + og-image (see "SEO assets"), and zed-coop.png
```

## Preview locally

Any static server works:

```bash
cd site && python3 -m http.server 8000
# open http://localhost:8000
```

## The homepage and the docs' terminals

`tools/gen_site.py` writes `index.html` from `tools/site/index.tpl.html`. It fills in the
parts that repeat, so nobody types them by hand: the icons, the provider marks
(`tools/site/logos/`), the terminal scenes and the commands you copy. When you regenerate,
the homepage's commit count adds up the `Coop-Task:` commits on `origin/main` of co:op, Emisar
(`../emisar`) and Ryker (`../responder`), so fetch all three first. A missing checkout stops the
script.

The script also fills the terminal windows in `docs.html`. You write the docs by hand,
except between a `<!-- gen_site: NAME -->` and `<!-- /gen_site -->` marker. There the
script writes the scene named `NAME`.

```bash
python3 tools/gen_site.py           # regenerate after editing the template or a scene
python3 tools/gen_site.py --check   # what make tools-test runs: fails if either page is stale
```

The terminal scenes copy the CLI's real output. `TERMINAL_SOURCES` lists the sources for
each terminal: the approved transcripts under `internal/cli/testdata/approved/` and the Go
code that prints each line. When that output changes, `--check` fails and names the page,
the terminal and the line. It keeps failing until the scene matches again.

Both pages load the stylesheet and scripts with `?v=` and a short hash of those files.
`tools/gen_site.py` writes the hash. Regenerate after you change any of them, since
`--check` fails until you do. Every browser then fetches the new copy instead of reusing a
cached one.

## Deploy

`.github/workflows/pages.yml` uploads `site/` to GitHub Pages on every push to `main` that
touches it, `install.sh` or the workflow itself, and you can also start it by hand. It publishes the
committed files, plus the repo's `install.sh` beside them, so `coop.dryga.com/install.sh` is always
the script on `main`.

You set it up once: in the repo, open Settings → Pages and set Source to "GitHub Actions".

## SEO assets

The favicon, app icons and social card under `assets/img/` are generated, and the results
are committed. `zed-coop.png` is the exception: it's a real Zed screenshot, cropped by hand (see
`.agent/kb/website.md`). `tools/gen_seo_assets.py` makes them with headless Chrome and ImageMagick. It
draws the icons from the brand's mark, `brand/assets/coop-flat.svg`. It renders the social
card from the homepage's own first screen.

```bash
python3 tools/gen_seo_assets.py          # regenerate everything
python3 tools/gen_seo_assets.py icons    # just the favicon / app icons
python3 tools/gen_seo_assets.py og       # just the 1200×630 social card
```

Regenerate the card after you change the homepage's hero. If the site ever moves off
`coop.dryga.com`, edit the canonical and `og:url` base, and `site/CNAME`.
