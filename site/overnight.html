Put your agents to work while you sleep

co:op gives you a way to set up hundreds of tasks and get them done securely, without supervision.

  1. Queue up the work

    Add tasks from your terminal or from Zed, or let your agents file what they find. Each task is a folder that says what to do and how to tell it’s done.

    88% of real requests to coding agents gave only the problem, with little else, against 7% of benchmark tasks, a 2026 study found.

  2. A fresh agent for every task

    The loop takes the queue one task at a time. Each task starts a fresh agent session, so it doesn’t drag the last task’s context along.

    39% average drop when top models got a task over several turns instead of in one message, a 2025 study found.

  3. Checked and committed

    The agent runs your checks before it calls a task done, then commits the work: one commit per task.

    22.6% of the failures found in 20,574 real coding-agent sessions were the agent claiming it was done too early, a 2026 study found.

  4. Accounts rotate when rate limited

    When an account reaches its usage limit, the loop carries on with the next one.

    20 hours a week is how long the average Claude Code user now has it running, Anthropic found.

  5. Questions don’t stop the work

    A task that needs your call is set aside with its options and a recommendation, and the loop moves on to the next.

    92.3% of coding-agent session time went to waiting on the person, a 2026 study of 4,300 sessions found.

  6. Reviewed before you wake up

    A final review holds every task to what you asked for, and sends back anything that falls short.

    About half of agent pull requests that passed the tests still wouldn’t have been merged by the project’s maintainers, METR found.

  7. Good morning

    Review the commits, answer the waiting question, and queue tonight’s work.

    1,300+ pull requests merged at Stripe each week are written start to finish by unattended agents and reviewed by people, Stripe reported.

Safe to leave running

  • Only your project is in reach.
  • Secrets read as empty files.
  • Restricted networking: only your AI provider and approved sites.
  • Only you can push.

42% of reported coding-agent file mishaps reached outside the project, into system files, personal files and secrets, a 2026 study found.

How the sandbox works→

The loop and the sandbox are just the start. co:op gives you these too.

  1. Project services

    Postgres, Redis and the rest of your Compose file run beside the box, each in its own container.

    A loop gets its own set for the whole run, apart from yours, and removes it when the run ends.

    6.5 s to start the box with Postgres and Redis beside it, once their images are pulled, we measured.

  2. Presets

    A preset is a lead model and the roles it calls on: a thinker, a critic, and a fast one for the busywork.

    +18 points on competitive programming problems when Claude reviewed Codex’s drafts, against +13 when Codex reviewed its own, a 2026 study found.

  3. Forks

    Run several loops at once, each in its own copy of your project, and every task is claimed exactly once. Review each fork like a pull request, then merge it.

    16 agents in their own copies, each task claimed by one, built a 100,000-line C compiler that builds Linux, Anthropic reported.

  4. Integrations

    Zed makes a great cockpit: plan with the sandboxed agent in its agent panel, and have it add the tasks to your queue for the loop.

    Any editor that speaks ACP works too, with account rotation built in.

Get started

Free and open source. Runs on macOS and Linux with Docker.

Install$ curl -fsSL https://coop.dryga.com/install.sh | sh
Sign in$ coop login claude
Set up$ cd your-project && coop init
Start$ coop loop claude
